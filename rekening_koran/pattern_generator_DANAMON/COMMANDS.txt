===========================================
EXTRACTION LOGIC
===========================================

DANAMON uses Array[3] + Array[4] extraction:

Format: "KR OTOMATIS LLG-DANAMON [Array3] [Array4] [AdditionalInfo]"

Smart Extraction:
-----------------
- If Array[3] is "PT" or "CV":
  → Take Array[3] + Array[4] + Array[5]
  
- Otherwise:
  → Take Array[3] + Array[4]

Examples:
---------
Input:  "KR OTOMATIS LLG-DANAMON PT TRISULA ADI TEGUH BUKTI BAYAR"
Output: "PT TRISULA ADI"
        (Array[3]="PT" → takes 3 words)

Input:  "KR OTOMATIS LLG-DANAMON KOPERASI KARYAWAN GREENFIELDS INDONESIA"
Output: "KOPERASI KARYAWAN"
        (Array[3]≠"PT/CV" → takes 2 words)


===========================================
TROUBLESHOOTING
===========================================

Problem: Compilation errors
Solution: Check if gcc is installed: gcc --version

Problem: File not found when running
Solution: Make sure you're in the correct directory:
          pwd
          Should show: .../pattern_generator_DANAMON

Problem: No patterns generated
Solution: Check if DANAMON.csv exists and has data:
          head DANAMON.csv
          wc -l DANAMON.csv

Problem: test_btp_pattern shows "NO PATTERN FOUND"
Solution: 
1. Check if master_customer_btp_pattern_DANAMON.sql was generated
2. Verify the description format matches:
   "KR OTOMATIS LLG-DANAMON [WORD1] [WORD2] ..."
3. Use option 'A' to see all available BTPs
4. Use option 'B' to see latest BTPs


===========================================
NOTES
===========================================

- CSV format: BTP;Description
- Separator: semicolon (;)
- First line is header (skipped)
- BTP can be numeric or non-numeric (e.g., "MODERN TRADE")
- Customer names are case-insensitive for matching
- Match percentage = (BTP count / Total customer transactions) × 100%
- Last line number tracks the most recent usage of each BTP
- Smart extraction handles "PT" and "CV" prefixes automatically
